## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Lovelace config -> shared normalizer/editor | Dashboard config is user-controlled and may include missing, unknown, or future keys. |
| Card -> Home Assistant calendar API | Entity IDs and date ranges cross into the authenticated Home Assistant client. |
| Source -> generated distribution bundle | A minified public artifact must correspond to reviewed TypeScript source. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-04 | Tampering | Layout discriminator | mitigate | Allowlist exact `wall`; route missing, `default`, case variants, objects, and unknown values to legacy behavior with unit tests. |
| T-01-05 | Tampering / Information Disclosure | Editor round-trip | mitigate | Serialize immutably from the complete raw config; delete Default only; preserve unknown keys and nested values in tests. |
| T-01-06 | Spoofing / Information Disclosure | Calendar read adapter | mitigate | Accept only the existing authenticated `hass.callApi` boundary; add no direct network client, external endpoint, or token field. |
| T-01-07 | Denial of Service | Calendar fan-out | mitigate | Preserve the current deduplicated calendar set and existing stable fetch key; do not add extra reads or retries. |
| T-01-08 | Tampering | Generated bundle | mitigate | Never edit `dist` manually; regenerate through the locked Rollup command after source review and run the build gate. |
